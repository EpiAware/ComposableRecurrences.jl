Performance and trimming ​

A new type can be made fast, specialised and trimmed, building on Writing new types.

Fast methods ​

  • Keep forward! and pullback! free of allocations: loop with eachindex over the arrays you index, write in place, and add @inbounds only to such loops.

  • Use concrete field types through type parameters, so every call is type stable.

The benchmark matrix times the gradient of a renewal with a stateless pointwise modifier, the saturation   in benchmark/docs_modifier.jl, under Mooncake and Enzyme in reverse mode. It times plain AD of the whole operator, the rule with forward! only, and the rule with the pullback!.

With forward! only, the gradient takes 46% to 87% of the time of plain AD. At T 200 and L 20 that is 46% on Mooncake and 77% on Enzyme. The pullback! then takes it to 83% to 99% of the time with forward! only. These are median times at revision d41af96e.

The local step evaluates forward! once per step with dual numbers, so its cost follows the cost of forward!. For a map as cheap as the saturation there is little for a pullback! to save. Write forward! first, and add a pullback! when timing shows the modifier's local step matters.

Trimmed executables ​

On Julia 1.12 and later, juliac --trim=safe compiles an app into an executable that holds only the code the app can reach. The build fails on any call the compiler cannot resolve from the argument types. A build can pass and still fail when run, for example on a call the runtime makes, so the app is run as well as built.

The app in test/trim checks the forward path of each operator, a depletion with flows, a derived parameter and a Threaded loop. The Trim workflow builds and runs it when src or the app changes. Its operator calls run serially, as a trimmed app cannot set EXECUTOR with with on Julia 1.12, and gradients and the extensions are not trim-tested. A new type used in a trimmed app needs concrete field types, and methods whose calls resolve from the argument types.

To run the check locally, with JuliaC installed in a shared environment:

bash
julia --project=@juliac -e 'using Pkg; Pkg.add("JuliaC")'
cd test/trim
julia --project=. -e 'using Pkg; Pkg.instantiate()'
julia --project=@juliac -e 'using JuliaC; JuliaC.main(ARGS)' -- \
    --output-exe trimapp --bundle build --trim=safe --experimental .
build/bin/trimapp

Specialising for speed ​

Every call of an operator has one form, and the work behind it is chosen by dispatch on the types of its kernel, coupling, modifiers and numbers. A method for a narrower type replaces the general one for that type alone, so a faster path for one combination needs no new interface and no change to any call.

a coupling with structure, such as low rank or bandedforward!(C::MyCoupling, Pressure(), q, p, t), and its pullback!

a depletion form at one number typeforward!(form::MyForm, Step(), v::AbstractVector{Float32}, s::AbstractVector{Float32}, N::Float32)

julia
struct RankOne{V}
    u::V
    w::V
end
function CR.forward!(C::RankOne, ::CR.Pressure, q, p, t)
    c = zero(eltype(q))
    for b in eachindex(p)
        c += C.w[b] * p[b]
    end
    for a in eachindex(q)
        q[a] = C.u[a] * c
    end
    return nothing
end

u, w = [0.9, 0.1, 0.4], [0.5, 0.3, 0.2]
R = fill(1.2, 3, 6)
h = ones(3, 2)
low = Recurrence([0.5, 0.5]; coupling = RankOne(u, w))(R; history = h)
dense = Recurrence([0.5, 0.5]; coupling = u * w')(R; history = h)
low ≈ dense
true
